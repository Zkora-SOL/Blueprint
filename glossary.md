# Z-Kora Glossary
Supporting services that operate outside the blockchain (e.g., relayers, proof services) and improve usability without custody over user assets or data.


---


## Non-Custodial


A system design where users retain full control over their private keys and assets at all times, without trusting third parties.


---


## Metadata Leakage


The unintended exposure of information such as timing, frequency, or interaction patterns that may compromise privacy even if data is encrypted.


---


## Threat Model


A formal description of security assumptions, adversaries, and risks that a system is designed to handle or explicitly exclude.


---


## Modular Architecture


A system design approach where components are built as independent modules that can be developed, upgraded, or integrated separately.


---


## Trust Assumption


An explicit statement about which components or parties must be trusted for the system to remain secure.


---


## ZK-Pay


The Z-Kora module responsible for enabling private, shielded payments using zero-knowledge proofs.


---


## ZK-ID


The Z-Kora module that enables privacy-preserving identity proofs and selective disclosure.


---


## ZK-Storage


The Z-Kora module that enables encrypted file storage and access control using zero-knowledge proofs.


---


## ZK-Interact


The Z-Kora module that enables private interactions with smart contracts without revealing user intent or behavior.


---


## Privacy-by-Default


A design principle where systems are built to minimize data exposure automatically, without requiring users to opt in.


---


## Auditability


The ability for third parties to verify correctness and security properties without accessing sensitive user data.


---


## Summary


This glossary is intended to evolve alongside the Z-Kora protocol and should be updated as new concepts and modules are introduced.
